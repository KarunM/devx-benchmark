# DevX benchmark facts (benchmark sections extracted from the maintainer's FACTS file)

## live-agent benchmark (2026-10-12, DevX 1.7.0 = commit 04a02ef)

Sources: `results/series4/rows.csv`, `results/series5/rows.csv`, `rescore.csv` (hand-checked, blinded correctness for series 5), report Table 1.1 in `BENCHMARK-REPORT.md`. All figures recomputed from the CSVs on 2026-10-12. Agent: Codex CLI, one model. Arm C = DevX on PATH plus shipped guidance; arm N = shell only (grep/rg/sed/cat). Savings are shares of the native arm.

- [F-LA-1] First article (2026-03-02) headline: ~88k tokens across 4 cycles before, ~11.2k after, ~87% reduction. It measured the author's own chat sessions after workflow changes (build summaries, narrow context, fixed output shape). It did not measure DevX.
- [F-LA-2] Series 5 held-out: 12 tasks, 2 arms, 1 rep = 24 runs, both arms read-only. Correct 10/12 each arm. 6 tasks on a Python fixture (sympy), 6 on a copy of DevX's own C# source.
- [F-LA-3] Series 5 both-correct n=8 (excludes H-R2): calls 9 vs 12 (25.0% fewer), input tokens 240,425 vs 271,897 (11.6% fewer), result bytes 12,701 vs 24,152 (47.4% fewer).
- [F-LA-4] H-R2 native arm returned 358,121 B from one `rg -C 5` over a tree containing a tracked `.bak` file. Including it (n=9): 26.7% / 15.0% / 95.5% fewer; calls 11 vs 15; bytes 17,251 vs 382,273.
- [F-LA-5] Series 5 all 12 tasks: calls 16 vs 17, input tokens 101% of native (405,003 vs 399,597), result bytes 8% of native.
- [F-LA-6] Series 4 tuned: 12 tasks x 2 arms x 3 reps = 72 runs, arm C workspace-write, N read-only. Correct 36/36 (C) vs 33/36 (N).
- [F-LA-7] Series 4 sum of per-task medians, C as share of N: calls 131%, input tokens 124%, result bytes 69%. Both-correct n=10: 120% / 116% / 48%.
- [F-LA-8] Series 4 per kind, C%N calls/input/bytes: locate 100/107/28, read 100/102/15, structure 100/106/102, crossref 100/107/129, multihop 300/223/167.
- [F-LA-9] Four wrong series-5 answers, two per arm. Two were runs with zero tool calls (H-M1 arm C, H-S1 arm N).
- [F-LA-10] C# `callers` on an overloaded method fails ("matched multiple implementations", rc 1), series 5 H-X2 arm C: 4 calls and 14,239 B against native 1 call and 2,555 B. Not fixed.
- [F-LA-11] Paid Codex runs total 186.
- [F-LA-12] Fixed input of about 26,000 tokens per run (prompt and guidance) dominates token totals.
- [F-LA-13] Qualifiers: one repetition, one model, blinded manual scoring, read-only workflows, the C# fixture is DevX's own source. No claim of lower cost, general superiority or statistical significance.
- [F-LA-14] Approved sentence: "In a 12-task held-out, read-only repository benchmark using one coding model, DevX and native grep workflows each completed 10 tasks correctly. On the eight tasks both completed correctly, DevX required 25% fewer tool calls, 12% fewer model input tokens, and 47% fewer tool-result bytes."
- [F-LA-15] Product changes (report section 3): `read type` returns an outline by default (Symbol 7,404 B to 1,216 B); text-backed Python `references`/`callers`; resolved `bases:` line in the outline; `callers` grouped by enclosing symbol (`_symbol` 4,923 B to 1,068 B); guidance block of about 2.9 KB teaching bare names and outlines. Tuned on the series 1-4 tasks.
- [F-LA-16] Known defects: C# `callers` overload failure and over-reporting; Python `callers` counts doctest lines; `--full` wording invites listing every site; single-line locate returns 383-1,762 B where grep returns 53-813 B.
- [F-LA-17] Arm D (MCP) trial used about 2.3x the input tokens of native (74,215 vs 31,433) and was dropped.
- [F-LA-18] 168 scored benchmark rows (series 1-3: 24 each; series 4: 72; series 5: 24) within the 186 paid runs. The 186 includes 18 trial, smoke and isolation runs.
- [F-LA-19] Series 5 scoring: automated substring check against a fixed answer key; blinded rescore of all 24 answers by a second coding agent (arm hidden, `rescore-blind.csv`, 20/24 correct); author's unblinded review (`rescore.csv`). Blinded rescore agrees with the final verdicts on all 24 (per-task pairs); the automated check differed on one (H-S1 arm C, scored 1, final 0). Blinded but not independent.
- [F-LA-20] The first article never mentions DevX; its 87% headline concerned the author's chat habits (see F-LA-1).

## Multi-model held-out comparison (2026-10-12, series 6-9, same DevX build 04a02ef)

Sources: `results/series{5,6,7,8,9}/rows.csv` joined with the verified verdicts `rescore.csv` (series 5), `results/series6/rescore6.csv`, `results/series7/rescore7.csv`, `results/series8/rescore8.csv`, `results/series9/rescore9.csv`; per-series notes `SERIES6.md`-`SERIES9.md`. All figures recomputed from the CSVs on 2026-10-12. Efficiency ratios are DevX (arm C) divided by native (arm N) on tasks both arms answered correctly; below 100% means DevX used less. Same 12 held-out tasks, same DevX binary (1.6.14+04a02ef444bf, product 1.7.0), read-only workflows, one repetition per cell, 24 runs per series.

- [F-MM-1] Series 5 (baseline): model gpt-6-luna through Codex CLI (codex-cli 0.155.1), reasoning effort `medium` (from config.toml). Verified correctness C 10/12, N 10/12 (`rescore.csv`). Both-correct n=9 including the outlier task H-R2: calls C 11 vs N 15 (73%); input tokens 283,601 vs 333,473 (85%); result bytes 17,251 vs 382,273 (5%). The 5% includes the 358,121 B native search result of F-CS22 (H-R2). All 12: calls 16 vs 17 (94%), tokens 405,003 vs 399,597 (101%), bytes 31,958 vs 385,283 (8%). Automated scorer agrees with the verified verdicts on 23/24 answers (H-S1 arm C differs).
- [F-MM-2] Series 6: model gpt-5.6-luna via Codex CLI 0.155.1, reasoning effort `medium`. Verified correctness C 12/12, N 12/12 (`rescore6.csv`). Both-correct n=12: calls 22 vs 20 (110%); input tokens 438,875 vs 423,045 (104%); result bytes 42,090 vs 1,167,598 (4%). All-12 line identical. Automated scorer and blinded rescore agree 24/24. DevX increased calls and input tokens here; native arm H-R1 returned 1,051,628 B in one command.
- [F-MM-3] Series 7: model `deepseek-flash` (metadata name DeepSeek-V4.1-Flash) through Codex CLI 0.155.1 using `-c` provider overrides (model_provider deepseek, wire_api responses). Reasoning effort printed `medium`; the provider lists low/high/max, so whether `medium` is honoured is unknown. Verified correctness C 12/12, N 12/12 (`rescore7.csv`). Both-correct n=12, after dropping the "Model metadata not found" pseudo-call the parser counts once per run (SERIES7.md): calls 19 vs 34 (56%); input tokens 1,097,629 vs 1,599,417 (69%); result bytes 26,768 vs 33,848 (79%). All-12 line identical. Automated scorer and rescore agree 24/24.
- [F-MM-4] Series 8: model claude-sonnet-5-5 via Claude Code headless (2.1.296), `-p --output-format stream-json`, tools Bash/Read/Grep/Glob allowed, Edit/Write/NotebookEdit disallowed; reasoning effort not set by the harness (default; not recorded). Verified correctness C 12/12, N 11/12 (`rescore8.csv`). Both-correct n=11: calls 16 vs 18 (89%); input tokens 539,293 vs 537,944 (100%); result bytes 22,630 vs 14,550 (156%). All 12: calls 18 vs 19 (95%), tokens 599,063 vs 574,979 (104%), bytes 23,553 vs 14,734 (160%). Automated scorer and rescore agree 23/24 after rulings.
- [F-MM-5] Series 8 ruling: H-M1 arm N, rescorer verdict incorrect UPHELD (answers "The class is C89CodePrinter" and gives CodePrinter only as chain context; the reference asks for CodePrinter at codeprinter.py:53; same rule as series 6).
- [F-MM-6] Series 9: model claude-sonnet-5 via Claude Code headless (2.1.296), same argv and effort as series 8. Verified correctness C 12/12, N 10/12 (`rescore9.csv`). Both-correct n=10: calls 17 vs 29 (59%); input tokens 774,121 vs 1,052,377 (74%); result bytes 31,743 vs 18,509 (172%). All 12: calls 19 vs 36 (53%), tokens 886,189 vs 1,331,443 (67%), bytes 35,935 vs 25,992 (138%). Automated scorer 11/12 for N; automated and rescore agree 23/24 after rulings.
- [F-MM-7] Series 9 rulings: H-M1 arm N rescorer incorrect OVERRIDDEN to correct (asked elements CodePrinter and codeprinter.py:53 right; wrong line on the unasked intermediate class immaterial). H-X1 arm N incorrect UPHELD (swapped callers, mid-answer "wait, let me clarify"). H-R2 arm N incorrect UPHELD (final message was a background-search status line, kept as a failed row, not rerun).
- [F-MM-8] Aggregate verified correctness over series 5-9: DevX 58/60 (10+12+12+12+12) versus native 55/60 (10+12+12+11+10). DevX misses (2): series 5 H-M1 (zero tool calls, wrong class) and series 5 H-S1 (listed underscore names). Native misses (5): series 5 H-S1 (refused, zero calls), series 5 H-X2 (DoctorAsync missing), series 8 H-M1, series 9 H-R2, series 9 H-X1.
- [F-MM-9] Isolation for Claude Code runs: `--setting-sources project,local` alone did NOT exclude the user's global instructions that mention DevX. With CLAUDE_CODE_DISABLE_CLAUDE_MDS=1 and CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 set and parent CLAUDE*/ANTHROPIC* environment variables dropped, the native-arm probe asked to quote any DevX instruction answered exactly `NONE`. Fixture listings with checksums before and after were identical.
- [F-MM-10] Claude Code tools return bounded output (Read numbered window with offset/limit, Grep bounded match list), whereas the Codex shell returns whatever a command prints. This is why result bytes run the other way on Claude Code (156% and 172%) than on the Codex path (4-5%).
- [F-MM-11] Caveats: one repetition per cell; the same 12 tasks are reused across all five series, so they are now a regression set, not a generalisation set; the harness differs between series 5-7 (Codex CLI) and 8-9 (Claude Code); DeepSeek input tokens include about 73k uncached baseline per run, so series 7 token figures are not comparable with series 5-6 in absolute terms; reasoning effort is not controlled across models.
- [F-MM-12] C# `callers` defect on `RipgrepLocator.Locate` (H-X2) failed in arm C on four of five configurations (series 5, 7, 8, 9) and the agent recovered with `search text` each time; the task was still answered correctly. This is a product defect (F-LA-10, F-LA-16), not a failed task.
- [F-MM-13] Paid and plan-run accounting: 238 runs on the Codex path in total; 48 Claude Code benchmark runs (series 8 and 9, 24 each) plus 4 isolation/model probes.

## Frontier and open-model held-out comparison (2026-10-12, series 10, 11, 13, 14, same DevX build 04a02ef)

Sources: `results/series{10,11,13,14}/rows.csv` joined with `rescore10.csv`, `rescore11.csv`, `rescore13.csv`, `rescore14.csv` (verdicts) and `rescore-blind<N>.csv` (blind ids); per-series notes `SERIES10.md`, `SERIES11.md`, `SERIES13.md`, `SERIES14.md`. Admitted to the evidence set by the maintainer on 2026-10-12. All figures recomputed from the CSVs on 2026-10-12. Ratios are DevX (arm C) divided by native (arm N) on tasks both arms answered correctly; below 100% means DevX used less. Same 12 held-out tasks, same DevX binary (1.6.14+04a02ef444bf, product 1.7.0), read-only workflows, one repetition per cell, 24 runs per series. Call counts exclude the Codex "Model metadata not found" warning that the parser records as an `other` item (same rule as F-MM-3); `tool_calls_total` in series 14 rows.csv includes it (1 per run), which would read 62% / 70% instead of 48% / 58%.

- [F-FM-1] Series 10: model `claude-opus-5-5` via Claude Code headless (same argv, isolation and effort handling as F-MM-4/F-MM-9; argv in `SERIES10.md`). Verified correctness C 11/12, N 11/12 (`results/series10/rescore10.csv`, `rescore-blind10.csv`); both arms missed H-M1. Both-correct n=11: calls 18 vs 23 (78%); input tokens 584,399 vs 635,280 (92%); result bytes 23,973 vs 14,826 (162%). All 12: calls 20 vs 24 (83%), tokens 643,759 vs 672,303 (96%), bytes 24,336 vs 15,058 (162%). Wall seconds summed over runs C 97.4 vs N 106.9. Automated scorer and blinded rescore agree 22/24 (the two H-M1 answers).
- [F-FM-2] Series 11: model `gpt-6-sol` via Codex CLI 0.155.1, reasoning effort `medium` (config), argv in `SERIES11.md`. Verified correctness C 12/12, N 11/12 (H-M1 native) (`results/series11/rescore11.csv`, `rescore-blind11.csv`). Both-correct n=11: calls 17 vs 19 (89%); input tokens 405,640 vs 422,764 (96%); result bytes 22,448 vs 76,422 (29%). All 12: calls 20 vs 20 (100%), tokens 465,035 vs 450,411 (103%), bytes 28,294 vs 76,607 (37%). Wall seconds C 125.2 vs N 104.9 (DevX slower here). Agreement 23/24.
- [F-FM-3] Series 13: model `claude-fable-5-1` via Claude Code headless (same argv as series 10, `SERIES13.md`). Verified correctness C 12/12, N 12/12 (`results/series13/rescore13.csv`, `rescore-blind13.csv`). Both-correct n=12: calls 16 vs 22 (73%); input tokens 610,717 vs 702,698 (87%); result bytes 20,850 vs 13,020 (160%). Wall seconds C 108.2 vs N 169.2 (64%). Agreement 24/24.
- [F-FM-4] Series 14: model `Qwen/Qwen3.6-27B` (fp8, DeepInfra, 262k context, $0.32/M input and $3.20/M output tokens) through Codex CLI 0.155.1 with `-c` provider overrides (model_provider deepinfra, wire_api responses; values in `SERIES14.md`). Codex reasoning effort `medium` from config; the usage reports 0 reasoning tokens, so whether it is honoured is unknown. Verified correctness C 11/12, N 9/12 (`results/series14/rescore14.csv`, `rescore-blind14.csv`); native misses H-S1, H-M1 and H-X2 (the H-M1 and H-S1 native runs made one command with no usable result, a `find /` that never returned, then answered from memory in one case); agreement automated vs blinded 23/24. Both-correct n=8: calls 10 vs 21 (48%); input tokens 503,441 vs 780,151 (65%); result bytes 15,511 vs 34,740 (45%). All 12: calls 18 vs 31 (58%), tokens 856,590 vs 1,219,008 (70%), bytes 39,569 vs 41,592 (95%). Wall seconds C 136.7 vs N 198.6. Spend about $0.75 (series $0.70 plus trial and probes about $0.05, per `SERIES14.md`).
- [F-FM-5] R-1, series 14 disputed row: H-X1 arm C, automated scorer correct, blinded grader `incorrect` ("extra wrong caller limit"); this is the only disagreement of 24. Final classification: INCORRECT. Rationale: the blinded rescore is the authoritative scorer in every series (`FREEZE-HELDOUT-2026-10-12.md` section 5); the answer lists a non-existent function `limit` as a caller because DevX's text-backed `callers` reported four module-docstring lines (gruntz.py:78,102,108,111) as module-level call sites and the model presented them as a function. Evidence: `results/series14/rescore14.csv` and `rescore-blind14.csv`. The reported 11/12 versus 9/12 already uses the adjudicated result (automated would read 12/12).
- [F-FM-6] R-2, nine-configuration totals (series 5, 6, 7, 8, 9, 10, 11, 13, 14; nine configurations on the same 12 tasks, 108 evaluations, not 108 tasks): verified correct DevX 104/108 versus native 98/108. DevX was wrong in four evaluations: series 5 gpt-6-luna twice (H-M1, H-S1), series 10 Opus H-M1 once, series 14 Qwen H-X1 once; of the four, the artifacts show exactly one traceable to a `callers` defect (series 14 H-X1, F-FM-10 docstring lines); series 5 H-S1 (listed underscore names) and H-M1 (zero tool calls) and series 10 H-M1 (two `read type` calls, wrong class) show no `callers` involvement. An earlier draft's wording "two of them traceable to `callers` defects" could not be verified from the artifacts and is not used. Native was wrong in ten: series 5 twice (H-S1, H-X2), series 8 once, series 9 twice, series 10 once, series 11 once, series 14 three times. On both-correct tasks DevX used fewer calls in 8 of 9 configurations (gpt-5.6-luna 110% is the exception), fewer input tokens in 7 of 9 (gpt-5.6-luna 104% and Sonnet 5.5 100% are not fewer), and fewer result bytes in 5 of 9 (series 5, 6, 7, 11, 14; the four Claude Code series 8, 9, 10, 13 return more). Note: an earlier draft of this count said 4 of 9 for bytes; recomputation gives 5 of 9. Never write "the only two wrong answers"; write "four wrong DevX answers, one of them traceable to a `callers` defect".
- [F-FM-7] Provider and key handling for series 14: the DeepInfra key lives only as a single KEY=VALUE line in a 0600 file outside the repository, loaded with `--env-file` from outside the repo and never logged; a search of `results/series14`, `results/trial-qwen-di`, `SERIES14.md` and `run_series14.sh` for bearer-token headers, authorization headers and key assignments returned 0 files on 2026-10-12. A separate local Ollama Qwen trial (`results/trial-qwen/`) was stopped after 4 of 6 runs because of stream disconnects and is parked; it is NOT evidence and is not used in any figure.
- [F-FM-8] Wall time, summed `wall_seconds` per arm: series 10 Opus C 97.4 s, N 106.9 s; series 13 Fable C 108.2 s, N 169.2 s. Fable is not faster than Opus in either arm (C +11%, N +58%); its DevX arm is 64% of its native arm, Opus's 91%. No "fastest model" claim is made. Series 8/9/11/14 for reference: Sonnet 5.5 C 107.6 vs N 160.5, Sonnet 5 C 127.1 vs N 530.3, gpt-6-sol C 125.2 vs N 104.9, Qwen C 136.7 vs N 198.6.
- [F-FM-9] H-M1 ("Name that class") was missed by Opus in both arms (series 10) and by gpt-6-sol natively (series 11), and by luna and Sonnet 5.5 earlier (F-MM-5, F-MM-7, F-MM-8). Standing ruling unchanged (reference CodePrinter at codeprinter.py:53); the question wording is loose and is to be tightened in a future task set, not retroactively.
- [F-FM-10] Two DevX `callers` defects seen across all series. (a) C# overload on H-X2 (`RipgrepLocator.Locate`, "matched multiple implementations"): fixed in 1.7.1 and verified in the maintainer's implementation notes (not published); the benchmark binary 1.6.14+04a02ef still has it. (b) Python text-backed `callers` counts module-docstring lines as call sites: found on H-X1 (`callers mrv_leadterm` returned `<module> 4 calls gruntz.py:78,102,108,111`); present in 1.7.1 too; open, fix scheduled for 1.7.2.
- [F-FM-11] Caveats: one repetition per cell; gpt-6.1-sol is not available on the account (HTTP 400 in `SERIES11.md`), so gpt-6-sol was used; Claude Code runs use the isolation environment of F-MM-9 (per-series NONE probe); the same 12 tasks are reused for every series, so they are a regression set; series 14 reasoning effort is not controlled; internally run, one repository pair, not independent.
- [F-FM-12] Paid and plan-run accounting added by these series: series 10 24 Claude Code runs plus 2 probes; series 11 24 Codex runs plus probes (4 across the model-id checks); series 13 24 Claude Code runs plus 2 probes; series 14 2 probes plus 6 trial runs plus 24 runs on DeepInfra (about $0.75); the stopped local Ollama trial 4 runs, unpaid. Totals with F-MM-13: 262 runs on the Codex path before counting DeepInfra, 96 Claude Code benchmark runs (series 8, 9, 10, 13) plus 8 probes; 32 DeepInfra runs (24 scored); 360 scored benchmark rows across series 1-14 (series 1-5 168, series 6-14 192); 398 agent runs in all.
